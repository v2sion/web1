차단성

제품의 심장이 이 계정에서 한 번도 안 돌려본 푸시 경로에 얹혀 있다

"항목마다 다른 시각에, 그 유저에게만" 보내는 푸시는 앱인토스 분류상 CONDITION_BASED 동의문 + type=SERVER 템플릿 + mTLS 파트너 서버 직접 발송 경로입니다. 토스가 대신 보내주는 SCHEDULED(cron) 경로로는 구현할 수 없습니다 — 만료 시각이 유저마다 제각각이기 때문입니다.

콘솔을 실제로 조회한 결과:

  • 워크스페이스 전체에 CONDITION_BASED 동의문 0건 (무더위 체감 랭킹·별핑계 모두 조회)
  • 별핑계가 가진 동의문 3건은 전부 SCHEDULED — 매일 9시 / 주말 14시 / 주말 여유
  • 푸시 템플릿 0건 — 이 계정은 푸시를 실제로 발송해 운영해 본 적이 없습니다

여기에 이미 알려진 함정 두 개가 겹칩니다. MCP push_template_create로 만든 기능성 푸시는 enabled:false로 고착돼 동의 팝업이 무반응이 됩니다 — 기능성 푸시는 콘솔 웹에서 직접 등록해야 하고, 개발 브리핑 6장에 이 내용이 없습니다. 그리고 알림 관련 SDK는 브라우저에서 조용히 no-op이라 dev 서버로는 구조적으로 검증되지 않습니다 — 2026-08-31 별핑계 알림 버튼 무반응이 라이브에서 수 주간 방치된 경로가 정확히 이것입니다.

권고 푸시를 Day 1 병렬이 아니라 Day 0, 앱 코드보다 먼저 관통시킬 것. mTLS 발급 → CONDITION_BASED 동의문 → SERVER 템플릿 1개 → 실기기 수신까지 스파이크로 확인한 뒤에 본 개발을 시작합니다. 동시에 푸시가 0명이어도 제품이 성립하는 폴백을 v1 기본 설계로 넣으세요 — ① 이미 검증된 SCHEDULED 동의문("매일 아침 9시, 오늘 만료되는 항목이 있어요")으로 48시간 정확도를 아침 배치로 낮추고, ② 앱 재진입 시 만료된 항목을 모아 한 번에 판정하는 인박스 패턴을 넣습니다. SERVER 직접 발송은 v1.1로 미루는 편이 리스크 대비 훨씬 낫습니다.

Postgres 신규 도입은 검증된 스택을 두고 새 의존성을 들이는 것

개발 브리핑 6장은 Vercel Postgres 또는 Neon 신규 도입을 제안합니다. 하지만 별핑계는 이미 Upstash Redis를 운영 중이고, 그 과정에서 얻은 함정(자동 역직렬화 가드 등)이 앱 CLAUDE.md에 축적돼 있습니다. 백서가 자랑하는 "운영비 0원 구조"도 새 DB를 들이면 흔들립니다.

이 앱이 서버에 실제로 요구하는 연산은 "만료 시각이 지난 항목을 시간순으로 꺼내기" 하나뿐입니다. Redis Sorted Set이 정확히 그 용도입니다 — ZADD score=expires_at / ZRANGEBYSCORE. 새 의존성 0, 이미 아는 함정, 이미 있는 계정.

브리핑이 Blob을 배제한 판단(B3)은 옳습니다. Blob은 쓰지 마세요.

권고 Postgres 대신 기존 Upstash Redis 재사용. 단 별핑계 프로젝트의 API 폴더를 건드리면 별점까지 영향을 받으므로, Redis 인스턴스는 공유하더라도 API는 jireumsin 프로젝트에 새로 두고 키 프리픽스를 분리하세요.

보험천재 반려는 카테고리가 아니라 "내용"으로 났다

보험천재는 생활 > AI > AI로 등록했는데도 "금융 서비스(보험)" 해당으로 출시 불가 통보를 받았습니다. 카테고리는 방패가 되지 않습니다. 재테크 카테고리 자체는 경쟁이 적어 노출 이점이 크니 유지하되, 심사자가 읽는 것은 콘솔 설명문과 앱 화면입니다.

이 앱의 안전한 자기정의는 "금액을 사용자가 직접 입력하는 개인 습관 도구"입니다. 그 선을 넘지 않게:

  • 콘솔 설명·키워드 금지어 — 재테크 수익, 투자, 자산관리, 금리, 적금, 할부, 카드, 상품 추천, 최저가
  • 권장 어휘 — 충동구매, 소비 습관, 대기, 참기, 기록, 다시 생각하기
  • 누적 절약액을 금융 자산처럼 보이게 하지 말 것 — 통장·저금통·잔액 은유와 원화 잔액 강조 UI는 피하고, "참은 금액 기록"으로 표현

AI 없음 → 고지·라벨 의무 해당 없음. 승패·점수 없음 → 게임 등급분류 불필요(더위배틀 경로 회피). Won't에 랭킹·친구 비교를 둔 판단이 이 안전선을 지켜줍니다.

검토

제품 설계에서 다시 볼 네 가지

48시간은 정말 최적인가

재진입까지 D+2입니다. 푸시 미동의자는 사실상 이탈이고, 대기 시간이 길수록 이 앱의 전환지표는 그대로 깎입니다. 기본 24시간 + 고액(예: 10만원 이상)만 48시간, 또는 사용자가 24/48/72를 고르게 하는 안을 검토하세요. "지름신 대기실"이라는 이름은 시간을 고정하지 않으므로 브랜드 손실이 없습니다.

대표 전환지표의 분모 문제

"최종판정 완료율"은 좋은 선택이지만 분모가 등록이라, 등록만 하고 안 돌아오는 유저가 지표를 끌어내립니다. 보조 지표로 등록 → 만료 후 재진입률을 함께 보세요. 푸시 효과를 분리해서 볼 수 있는 유일한 축입니다.

첫 진입 화면이 "0원 + 빈 리스트"다

히어로가 "지금까지 아낀 돈 0원"이고 그 아래가 빈 상태면 첫인상이 공허합니다. 디자인 브리핑에 빈 상태 시안은 있지만 0원 히어로 자체의 어색함은 아직 해결돼 있지 않습니다. 첫 방문에는 히어로를 절약액 대신 가치 제안 문구로 바꾸고, 첫 항목을 등록한 뒤부터 절약액 히어로로 전환하는 편이 자연스럽습니다.

공유 동기가 구조적으로 약하다

백서 8-1의 검증된 구조(1인칭 + 실수치 + CTA)는 지켰지만, "참은 것"은 "가진 것"보다 자랑 동기가 약합니다. 무더위 체감 랭킹의 "상위 N%" 같은 비교축이 이 앱에는 없습니다. 랭킹은 Won't에 두되, 개인 등급·칭호(예: 참기 레벨) 정도의 자랑거리를 공유 카드에 넣는 안을 검토하세요.

결과 직후 전면 광고는 이탈 지점이 될 수 있다

"안 샀어요"로 성취감을 준 직후가 감정적으로 가장 좋은 순간인데, 그 위에 전면 광고를 덮으면 그 순간을 광고와 맞바꾸게 됩니다. 결과를 충분히 보여준 뒤 홈 복귀 시점으로 광고를 미루는 배치를 함께 실험하세요. 백서 8-5(주 콘텐츠가 자리잡은 뒤 부가 UI)와 같은 원칙입니다.
