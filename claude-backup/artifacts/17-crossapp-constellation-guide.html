크로스앱 별자리 연동 가이드

별점 × 핑계운세를 시작으로, 앱 간 행동 데이터를 공유해 단일 앱에서는 절대 발견할 수 없는 별자리를 해금시키는 시스템의 설계 원칙과 구현 명세.

section 01
왜 크로스앱 별자리인가

별점의 별자리 수집은 단일 앱 내 반복 행동에서 의미를 찾는 메커닉이다. 그런데 두 앱 모두 같은 세계관(우주 / 별 / 핑계)을 공유하고 있다. 유저가 별점에서 스스로 낮은 점수를 주고, 곧이어 핑계운세에서 이유를 찾는 행동 패턴은 — 앱 안에서 각각 보면 분리된 이벤트지만 — 합쳐 보면 하나의 이야기가 된다.

크로스앱 별자리는 이 이야기를 포착한다. 유저는 "내가 두 앱을 어떻게 써왔는지"가 눈에 보이는 시각적 기억으로 남는다는 걸 나중에서야 발견하게 된다. 조건을 미리 노출하지 않는다는 별자리 원칙은 여기서도 동일하게 적용된다.

  • 익명성 계정 없음. 기기 고유 UUID만 사용. 어디에도 개인 식별 정보를 저장하지 않는다.
  • 단방향 이벤트 앱은 이벤트를 발행(publish)하고 각자 소비(consume)한다. 앱 간 직접 통신은 없다.
  • 느슨한 결합 한 앱이 없어도, 이벤트를 아직 보내지 않아도 나머지 앱이 정상 작동해야 한다. 크로스 별자리는 빠져도 기본 별자리는 정상 동작한다.
  • 발견의 순수함 조건을 인앱에서 절대 노출하지 않는다. 힌트는 "특별한 방법으로 나타납니다"로만 표시한다.
section 02
아키텍처 개요

두 앱은 이미 같은 Vercel 백엔드(star-excuse.vercel.app)와 Upstash Redis를 공유하고 있다. 새 엔드포인트 두 개만 추가하면 된다.

POST /api/cross-event

Toss 미니앱은 앱마다 별도 WebView에서 실행되므로 localStorage가 격리된다. 두 앱이 동일한 universe_device_id를 갖도록 별점이 핑계운세를 열 때 deep link 파라미터로 UID를 전달한다.

핵심 제약 — 첫 번째 연결은 반드시 별점→핑계운세 방향이어야 한다. 핑계운세를 먼저 독립 설치한 유저는 UID가 달라 크로스 별자리가 발견되지 않을 수 있다. 이 경우는 수용 가능한 엣지케이스로 간주한다.
section 03
DeviceId 전파 방식

두 앱이 공통 universe_device_id를 공유하는 절차.

1
starrating · 초기화 시
universe_device_id가 localStorage에 없으면 UUID v4 생성 후 저장. 이미 있으면 재사용.
2
starrating · 결과 뷰에서 핑계운세 버튼 탭 시
deep link 파라미터에 UID와 별점 컨텍스트를 포함해 핑계운세를 오픈한다.
intoss://starexcuse?_src=starrating&_uid=<uuid>&_score=2&_date=20260808
3
starexcuse · 앱 로드 시
URL params에서 _uid 읽어 universe_device_id로 localStorage에 저장. _src=starrating이면 cross-event POST 전송.
4
starrating · 별자리 체크 시
/api/cross-data?uid=<uuid> 호출 → Redis에 기록된 크로스 이벤트를 가져와 새 별자리 check 함수에 전달.
// 두 앱 공통 — 최초 실행 시 UID 확보
function getOrCreateDeviceId() {
  const KEY = 'universe_device_id';
  let uid = localStorage.getItem(KEY);
  if (!uid) {
    uid = crypto.randomUUID();
    localStorage.setItem(KEY, uid);
  }
  return uid;
}

// 별자리 지도 진입 시 크로스 이벤트 가져오기
async function fetchCrossEvents() {
  try {
    const r = await fetch(`${API_BASE}/api/cross-data?uid=${_uid}`);

    return events ?? [];
  } catch { return []; }
}

section 07
핑계운세 앱 변경사항
  • src/main.js (또는 app entry)
    앱 로드 시 URL searchParams에서 _uid, _src, _score, _date 파싱.
  • src/main.js
    _uid 값이 있으면 universe_device_id로 localStorage에 저장. 없으면 기존 저장값 사용, 그것도 없으면 새로 생성.
  • src/main.js
    _src === 'starrating'이면 즉시 /api/cross-event에 { uid, src: 'starexcuse', type: 'visit', payload: { date: _date || todayKST(), score: +_score || null } } POST.
// 핑계운세 app entry — 크로스 진입 처리
const params = new URLSearchParams(location.search);
const _src   = params.get('_src');
const _uid   = params.get('_uid');
const _score = params.get('_score');
const _date  = params.get('_date');

if (_uid) localStorage.setItem('universe_device_id', _uid);
const uid = localStorage.getItem('universe_device_id')
          ?? crypto.randomUUID();

if (_src === 'starrating' && uid) {
  fetch(`${API_BASE}/api/cross-event`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      uid,
      src: 'starexcuse',
      type: 'visit',
      payload: { date: _date ?? todayKST(), score: _score ? +_score : null },
    }),
  }).catch(() => {}); // 실패 시 무시
}
section 08
Vercel API 파일 추가

두 파일 모두 핑계운세/개발/app/api/에 추가. _lib/redis.js는 변경 없이 그대로 사용.

// api/cross-event.js
import { redis, setCors } from './_lib/redis.js';

export default async function handler(req, res) {
  setCors(res);
  if (req.method === 'OPTIONS') return res.status(200).end();
  if (req.method !== 'POST') return res.status(405).end();

  const { uid, src, type, payload } = req.body ?? {};
  if (!uid || !src || !type) return res.status(400).json({ error: 'missing fields' });

  const key   = `cross:events:${uid}`;
  const event = JSON.stringify({ src, type, payload: payload ?? {}, ts: Date.now() });

  await redis.lpush(key, event);
  await redis.ltrim(key, 0, 499);
  await redis.expire(key, 31536000);

  res.json({ ok: true });
}
// api/cross-data.js
import { redis, setCors } from './_lib/redis.js';

export default async function handler(req, res) {
  setCors(res);
  if (req.method === 'OPTIONS') return res.status(200).end();

  const { uid } = req.query;
  if (!uid) return res.status(400).json({ error: 'uid required' });

  const raw    = await redis.lrange(`cross:events:${uid}`, 0, 499);
  const events = (raw ?? []).map(e => {
    try { return JSON.parse(e); } catch { return null; }
  }).filter(Boolean);

  res.json({ events });
}
section 09
향후 앱 확장 계획

같은 이벤트 스키마를 따르는 앱은 추가 인프라 없이 참여 가능. 각 앱은 진입 시 _src와 _uid를 URL로 수신하고 cross-event를 POST하면 된다.

누구게?
데일리 퀴즈에서 모두 맞춘 날의 별점 점수가 낮다면 → "탐정의 역설" 별자리. 세상을 꿰뚫어 봤지만 하루는 별로였던 날.
비눗방울 타임
비눗방울에 글을 남긴 날 별점이 3점인 날들이 쌓이면 → "평범한 날의 기록들" 별자리. 특별하지 않은 날을 나눈 흔적.
더위배틀
배틀에서 최고 순위를 달성한 날 별점이 1점이라면 → "뜨거운 실패" 별자리. 더위와 싸웠지만 하루는 졌다.
보험천재
보험 정보를 확인한 날 별점 점수가 낮다면 → "대비의 별" 별자리. 힘든 날일수록 내일을 준비했다.
새 앱 참여 체크리스트 — ① URL param에서 _uid / _src 읽기 ② universe_device_id localStorage 저장 ③ POST /api/cross-event에 이벤트 발행 ④ 별점 CONSTELLATIONS에 신규 별자리 추가 (check·getDates 함수 포함). 인프라 추가 없음.
